# 데이터 변경 이력 설계

 - 데이터 변경 이력 설계1: 변경 추적 컬럼
 - 데이터 변경 이력 설계2: 이력 관리

<br/>

## 1. 데이터 변경 이력 설계가 필요한 이유

 - __예시__
    - 이 상품의 가격이 원래 얼마였죠?
    - 고객이 주소를 언제 변경했나요?
    - 이 데이터를 누가 수정했나요?
    - 작년 이맘때 회원 등급이 어떻게 되어 있었나요?
 - __사례__
    - 가격 분쟁: 고객이 주문한 시점의 가격이 얼마였는지 알 수 없다.
    - 배송 주소 오류: 고객이 주소를 변경한 것인지, 시스템 오류인지 알 수 없다.
    - 감사 대응: 현재 한도만 알 수 있고 변경 이력이 없다면 심각한 규정 위반이 된다.

```sql
CREATE TABLE product (
   product_id BIGINT PRIMARY KEY AUTO_INCREMENT,
   name VARCHAR(200) NOT NULL,
   price INT NOT NULL,
   stock_quantity INT NOT NULL DEFAULT 0,
   status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'
);
```
<br/>

## 2. 변경 추적 컬럼 - 기본

 - __추가 컬럼__
   - created_at: 등록일시
   - created_by: 등록자
   - updated_at: 수정일시
   - updated_bt: 수정자
 - __장점__
   - 설계가 단순하다.
   - 애플리케이션 코드가 간단하다.
 - __언제 사용하면 좋을까?__
   - 이력이 중요하지 않은 마스터 데이터: 코드 테이블, 설정 테이블 등
   - 단순 운영 도구: 내부 관리용 데이터
   - 어드민 로그 정도의 용도: 누가 마지막으로 수정했는지만 알면 되는 경우
```sql
CREATE TABLE product (
    product_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(200) NOT NULL,
    price INT NOT NULL,
    stock_quantity INT NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',-- 변경 추적 컬럼
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(100) NOT NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    updated_by VARCHAR(100) NOT NULL
);
```
<br/>

## 3. 변경 추적 컬럼 - 변경 사유

 - __추가 컬럼__
   - change_type: 변경 유형 (PRICE_CHANGE, STATUS_CHANGE, STOCK_ADJUST 등)
   - change_reason: 변경 사유(자유 형식 텍스트)
 - __변경 유형 표준화__
   - 변경 유형(change_type)을 표준화해서 사용하는 것이 좋다.
   - CREATE: 신규 등록
   - PRICE_CHANGE: 가격 변경
   - STOCK_ADJUST: 재고 조정
   - STATUS_CHANGE: 상태 변경
   - INFO_UPDATE: 정보 수정(이름, 설명 등)
   - PROMOTION: 프로모션 적용
   - CORRECTION: 오류 정정
```sql
CREATE TABLE product (
    product_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(200) NOT NULL,
    price INT NOT NULL,
    stock_quantity INT NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    -- 기본 변경 추적 컬럼
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(100) NOT NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    updated_by VARCHAR(100) NOT NULL,
    -- 변경 사유 컬럼
    change_type VARCHAR(50),
    change_reason VARCHAR(500)
);
```
<br/>

## 4. 변경 추적 컬럼 - 감사(Audit) 컬럼

 - __추가 컬럼__
   - source_system: 변경이 발생한 시스템(WEB_ADMIN, API, BATCH, MOBILE 등)
   - client_ip: 요청이 발생한 클라이언트 IP 주소
 - __source_system 표준화__
   - WEB_ADMIN: 웹 관리자 화면
   - WEB_USER: 웹 사용자 화면
   - MOBILE_APP: 모바일 앱
   - API: 외부 API 연동
   - BAETCH: 배치 시스템
   - MIGRATION: 데이터 마이그레이션
   - MANUAL: 수동 DB 작업 (DBA 직접 수정)
```sql
CREATE TABLE product (
    product_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(200) NOT NULL,
    price INT NOT NULL,
    stock_quantity INT NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    -- 기본 변경 추적 컬럼
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(100) NOT NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    updated_by VARCHAR(100) NOT NULL,
    -- 변경 사유 컬럼
    change_type VARCHAR(50),
    change_reason VARCHAR(500),
    -- 감사 컬럼
    source_system VARCHAR(50),
    client_ip VARCHAR(50)
);
```
